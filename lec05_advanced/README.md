# 第5回・発展課題の比較実験

2026年11月22日に提供された `lec05_before.zip` のコードに合わせた実行セットです。

## 実行

Codespacesの `lecture-ai-engineering-2026` の直下にZIPを置き、展開して実行します。

```bash
python -m zipfile -e lec05_advanced.zip . &&
uv run python lec05_advanced/run.py
```

5問について、基本RAG・配布版Tree・改良版Treeをそれぞれ2回、合計30試行実行します。
成功済みの試行は保存され、同じ条件・同じコマンドで再開すると未完了分だけ実行します。
429・502・503・504は最大3回まで再試行します。待ち時間は30秒、60秒です。
それでも停止した場合、画面のエラーと `lec05_results.zip` を確認してください。

完了後は、リポジトリ直下にできる `lec05_results.zip` をダウンロードしてチャットに添付します。
この段階では回答の採点や提出は完了していません。実測ログと根拠を確認して提出文を仕上げます。

## 何を変えるか

`app/retrieval.py` のTree候補文作成を、追加する `app/tree_preview.py` に接続します。
題名・章見出しの重複、進捗表示、出典ヘッダーなどを除き、本文の冒頭を最大200文字で返します。
LLMで要約する処理ではなく、元の文章を抜粋する規則です。本文の言い換えは行いません。
選ばれたページの全文、ページID、講義・章の階層、検索対象の214ページは保持します。

`AIE_TREE_PREVIEW=original` で配布版の先頭文表示、`improved` で改良版に切り替えます。
比較器は方式ごとに自動設定するので、手動の切り替え操作は不要です。
通常の `uv run python -m app.agent --tree ...` は、改良後は既定で改良版を使います。
元コードは `lectures/05/advanced_backup/retrieval_before.py.txt` に保存します。

## 実験条件

- 全方式で同じ質問文、同じモデル `gemini-3.5-flash-lite`、同じ対象資料を使います。
- Treeのツール名・引数・指示文は、配布版と改良版でそろえます。
- モデルを変える場合は `--model モデル名` で明示します。別条件の結果は分けて保存します。
- 開発に使ったメモリ問と、単一ページ・章横断・資料に答えがない4問を区別します。
- 各問で方式の実行順を入れ替え、2回目は順番を逆にします。
- 各試行は独立したプロセス・新規の会話で行います。
- 正解の要点や根拠ページを記した評価基準はモデルに渡しません。
- ツールが返した本文を省略せずJSONに保存し、候補一覧と実際に全文を読んだページを分けます。
- 回答の正しさは実行後に本文と照合します。未評価を正答扱いしません。
- 資料に答えがない質問の対応は、通常の質問の正答率・引用充足率と分けて評価します。
- 生成API推定費用は埋め込み・索引構築や未計上の失敗試行を含む総費用ではありません。

## 初回ログで分かったこと

メモリ問では、基本RAG・配布版Treeとも中心的な3要点を満たしています。
配布版Treeはp.39・p.40のほかp.41も取得しました。p.39・p.40で必要な根拠はそろいます。
初回の実測は、基本RAG7.28秒／入力2,500、Tree31.96秒／入力11,045トークンでした。
この1回の結果だけを方式全体の順位とは扱いません。

改良版は候補が詳しくなるため、候補文自体の量は増えます。
その情報で必要なページを選びやすくなり、不要な本文取得や応答回数が減るかを実測します。
改善・悪化・変化なしをすべて記録し、根拠品質と負担の両面で採用を判断します。

## 出力

- `lectures/05/advanced_design/`：固定した評価問題と、APIを使わない事前確認。

- `lec05_results.zip`：この比較結果と、確認に必要なコードをまとめたファイル。

`lectures/05/answer.md` の既存内容は自動編集しません。
